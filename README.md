# Кредитный навигатор

**Путиенко Алексей Дмитриевич, БФБО-06-24, 3 курс.**
Курс «Интеллектуальные информационные системы».
Тема №37 «Условия кредитных договоров», группа сложности B.

## 1. Название и назначение

Я разрабатываю «Кредитный навигатор» — учебного помощника по обычному кредиту
наличными Т-Банка. Он находит нужные пункты в документах и объясняет их со ссылками.
Для MVP выбрал один продукт: так проще проверить, что условия разных кредитов
не смешиваются. Речь идёт о публичных условиях, а не о личном договоре клиента.

## 2. Предметная область и источники

Вопросы проекта: процентная ставка и ПСК, регулярные платежи, просрочка,
досрочное погашение. Я выбрал Т-Банк как известный российский банк, который
публикует общие условия и тарифы в текстовых PDF.

Используются три документа, полученные с официальных страниц банка и проверенные
через `pypdf`. Прямые ссылки, редакции и SHA-256 записаны в `sources.json`.
Снимок проверен 11.11.2026. Индивидуальную ставку по этим документам определить нельзя.

| Файл | Документ и редакция | Страниц | Что проверено |
|---|---|---:|---|
| `bank_conditions.pdf` | [Условия комплексного обслуживания](https://cdn.tbank.ru/static/documents/627ee150-0276-4a81-9d0c-8be1e265ae87.pdf), редакция 63; раздел кредитования — редакция 31 | 101 | Извлечён текст; п. 3.11 о досрочном погашении читается на стр. 41 |
| `cash_tariff.pdf` | [Тариф КН 5.0](https://cdn.tbank.ru/static/documents/loans-cashloan-tariff.pdf), код T-КН-5.0-261008 | 1 | Строки ПСК, ставки и штрафа извлекаются вместе со значениями и единицами |
| `cash_conditions.pdf` | [Общие условия потребительского кредита](https://cdn.tbank.ru/static/documents/docs-consumer-cash-loan.pdf), код ФЗ-КН-261008 | 3 | Читаются все три страницы таблицы, включая п. 15 об ответственности |

Всего в исходниках 105 страниц. Условия обслуживания длиннее ориентира 20–50
страниц, поэтому PDF оставлен целиком. Для поиска выбраны полный раздел
«Общие условия кредитования» (стр. 40–49) и оба документа по кредиту наличными.
Другие разделы полного PDF — вклады, карты и страховые программы — в поиск не входят.
Внутри раздела кредитования специальные условия других продуктов отмечаются
`product=other` и исключаются из ответа. Файл при этом не обрезается.

Результат проверки извлечения — `reports/source-checks.json`.
Документы определяют ответ на дату снимка; автоматического обновления тарифов нет.
Текст ФЗ-353 в корпус отдельно не добавлялся: правовые выводы по всему закону
проект не делает.

## 3. Целевая аудитория

Основной пользователь — начинающий сотрудник поддержки. Сейчас ему приходится
открывать несколько PDF и вручную искать нужные пункты. Помощник должен дать
короткое объяснение и ссылку, по которой сотрудник проверит ответ.
Второй пользователь — клиент с общим обезличенным вопросом. Система учебная
и не является официальным сервисом Т-Банка.

## 4. Пользовательские истории

1. Как сотрудник поддержки, я хочу найти диапазон ПСК и отличить его от ставки,
   чтобы не выдать публичный диапазон за индивидуальное условие.
2. Как сотрудник поддержки, я хочу узнать размер и порядок начисления штрафа,
   чтобы сверить общие условия с тарифом. В ответе нужны ссылки на оба источника.
3. Как клиент, я хочу понять порядок досрочного погашения, чтобы отличить
   пополнение счёта от подачи заявки на погашение.
4. Как сотрудник поддержки, я хочу попросить объяснить ответ проще,
   чтобы сохранить его смысл, числа и ссылки.
5. Как клиент, я хочу задать уточнение к первому вопросу после нескольких реплик,
   чтобы не повторять все условия заново.

## 5. Границы MVP

**Входит:**

- один банк и обычный кредит наличными по выбранному снимку документов;
- поиск по ставкам, срокам, штрафам и досрочному погашению;
- рубрикация `product → category` и исключение условий других продуктов;
- роли аналитика, сверщика и редактора, граф разрешённых переходов;
- RAG через MCP и ChromaDB, настоящая модель Ollama или GigaChat;
- ссылки на исходный файл и страницу;
- SQLite-память, отдельные сессии и очистка истории;
- веб-чат и готовый адаптер VK из шаблона;
- пять проверочных вопросов на П2; оценка триады и экономика — на будущих П6 и П8.

**Не входит:**

- решение об одобрении, кредитный скоринг и определение персональной ставки;
- кредитные карты, ипотека, кредиты под залог, другие банки и сравнение предложений;
- загрузка клиентских договоров, номера договоров и доступ к банковским счетам;
- расчёт личного долга и финансовые рекомендации;
- отдельный разбор страхования, OCR сканов и автоматическое обновление документов.

Первоначальный план с картой «Платинум» сужен до одного продукта до заполнения
подтверждённого Gold Dataset и до первых замеров. Поэтому вопрос по карте
из старой заготовки заменён; причины замен записаны в отчёте П2.

## 6. Метрики

Цели сохранены из первоначального ТЗ. Первые пять вопросов включают один вопрос
вне корпуса, поэтому поиск оценивается по четырём вопросам с шагом 25%.

| Слот | Что измеряется | Цель | Функция | Первый замер |
|---|---|---|---|---|
| Поиск | hit-rate@5: найден ожидаемый документ о кредите наличными | ≥75% из четырёх вопросов | `ingest.evaluate_retrieval()` | П2 |
| Ответ | Средняя Faithfulness: условия в ответе подтверждены фрагментами | ≥0,8 по десяти вопросам | `test_suite.judge()` | П6 |
| Расход | Входные и выходные токены за один эталонный диалог из трёх вопросов | ≤12 000 токенов | `finops.measure_dialog()` | П8 |

Планируемый замер П2 — сверка источников,
а не оценка качества текста ответа. Context Precision и Faithfulness отдельно
измеряются на П6; здесь эти оценки не подменяются ручной проверкой П4.

## 7. Персональные данные

Система не запрашивает ФИО клиента, паспорт, телефон и номер договора.
Но пользователь может самостоятельно написать их в вопросе. При GigaChat
текст вопроса и история будут отправлены во внешний API. В локальной Ollama
запрос обрабатывается на машине, где запущен сервер. Для демонстрации использую
Ollama и только обезличенные вопросы.

Распознавание ПДн и инъекций относится к П7. В первых пяти практиках автоматической
защиты от такого ввода ещё нет, поэтому в интерфейсе показано предупреждение.
SQLite не шифруется; история очищается для конкретной сессии. `.env`, БД,
журналы, индекс и модели исключены из Git. Это минимизация обработки данных
с учётом 152-ФЗ, а не готовая банковская система хранения клиентских данных.

## Установка

Проверено: Linux x86_64, Python 3.12.14, CPU без CUDA. Подходит WSL.
Рекомендуется Python 3.11.8–3.12, 16 ГБ RAM и около 15 ГБ свободного места.
На macOS нужно установить Ollama отдельно; этот вариант здесь не проверялся.

```bash
bash scripts/setup.sh
source .venv/bin/activate
```

Скрипт ставит CPU PyTorch, зависимости с `constraints.txt`, делает `pip check`
и создаёт `.env` только при его отсутствии. Ключи в Git не добавляются.

### Восстановление PDF

Исходники не входят в бандл. Скачайте три PDF по ссылкам из таблицы в каталог
`materials`, затем импортируйте их: имена могут быть исходными, проверка идёт по SHA-256.

```bash
python scripts/import_sources.py materials
python scripts/check_sources.py
```

Если файлы ещё доступны по исходным URL в той же редакции, их можно получить
командой `python scripts/fetch_sources.py`. При другом хеше скрипт остановится,
чтобы случайно не заменить корпус новой редакцией.

### Поиск — с П2

```bash
python scripts/fetch_models.py embedding
python ingest.py
python ingest.py --eval
```

Использована Qwen3-Embedding-0.6B в исходном формате SentenceTransformers.
`config.get_collection()` и контракты шаблона не изменены. Изменена константа
пути к модели. На CPU веса загружаются в исходном BF16, длина ограничена 512 токенами.
В `models/registry-lock.json` закреплены OCI-digest моделей; скрипт проверяет
SHA-256 каждого файла. Модели получает официальный каталог Docker Models,
Docker daemon для скачивания не нужен. Дополнительный общий префикс инструкции
поиска не используется: функция эмбеддингов одинакова при записи и чтении.

### Настоящая модель — с П4

```bash
python scripts/fetch_models.py generation
python scripts/install_ollama.py
bash scripts/serve_ollama.sh
```

Последнюю команду оставьте в отдельном терминале. В другом терминале:

```bash
source .venv/bin/activate
.tools/ollama/bin/ollama create credit-qwen3:4b -f Modelfile
python scripts/smoke.py
streamlit run app.py --server.headless true
```

В `.env` выбран `LLM_BACKEND=ollama`, модель — Qwen3-4B-Instruct-2507 Q4_K_M.
Выбранная модель будет подключена на П4. Бэкенд `fake` остаётся только для отладки.
Для GigaChat нужны свой ключ в `.env` и доверенный TLS-сертификат; проверка TLS включена.

### Проверки

```bash
python -m unittest discover -s tests -v
python scripts/verify_live.py
```

Первая команда запускает быстрые тесты, включая настоящий обмен историей через
MCP и SQLite. Вторая использует настоящий индекс и Ollama: вопросы по документам,
контроль изменения контекста и диалог с продолжением в новом Python-процессе.
Результаты первых пяти практик — в `reports/`.

На П1 для проверки интерфейса достаточно установки и `streamlit run app.py`:
сквозной ответ ещё не требуется. Модули П6–П8 оставлены заготовками шаблона.
VK-адаптер не менялся; для запуска бота нужен свой `VK_TOKEN`, живое подключение
к VK в проверки не включалось.

## Сдача

Бандл каждой практики собирается по состоянию её коммита:

```bash
git bundle create Путиенко-П1.bundle --all
git bundle verify Путиенко-П1.bundle
```

Аналогично: `Путиенко-П2.bundle`, `Путиенко-П3.bundle`, `Путиенко-П4.bundle`,
`Путиенко-П5.bundle`. В каждом следующем сохраняется история предыдущих этапов.
Внутри находятся код, манифесты и отчёты; PDF, окружение, веса моделей и индекс
восстанавливаются отдельно по этой инструкции.
